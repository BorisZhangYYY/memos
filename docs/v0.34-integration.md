# v0.34 upstream integration

## Source and merge strategy

The integration branch is `codex/integrate-upstream-v0.34`. It merges upstream
`v0.31.0-rc.1` (`80832c0ad19dcc52b2df9fc08a9e3e435d0b09fc`) into the fork's
v0.33.6 history (`8820d7eaf68b90faed1863f103fe9ec92dfcaa83`). The merge keeps both
histories so later upstream merges can use Git ancestry. It does not replace
fork commits or use GitHub's Sync fork operation.

This is the agreed upstream target, not a claim that it remains the newest
upstream release. The fork publishes v0.34.0 through its manual tag workflow.

## Product behavior

- `/` remains the Memo editor and feed. A compact tabbed widget above it exposes
  mood, finance, and reminder summaries without replacing the default workflow.
  Its expanded/collapsed state is remembered locally.
- Mood stays integrated with the homepage calendar, Memo cards, and sidebar
  filters. The mood tab provides the focused history view and links back to the
  matching Memo.
- Finance entries are created from the homepage widget. Wallet and category
  management opens in a dialog from that same widget instead of occupying a
  separate Settings section.
- Reminder management opens as a focused homepage dialog. The All view groups
  records by list and gives each populated list its own creation target; opening
  a draft focuses its title without scrolling the list.
- The legacy `/personal` and `/reminders` URLs redirect to the homepage and keep
  compatible query parameters so old links continue to open the intended UI.
- Personal Features settings can disable mood, finance, and reminders separately
  or all at once. Disabled features remove their editor controls, dashboard tabs,
  notification entries, and associated client queries while leaving Memo content
  intact.
- Personal panels can use tag-style visual blurring, with optional account
  password verification. The verified app session is shared by the personal
  widget, configured tag-blurred Memos, and reminder-linked Memos; a single Memo
  can be re-locked without locking the whole session.
- The official editor, inline images, attachment handling, Saved Views, rich link
  previews, Space navigation, feed columns, and Memo detail improvements are
  retained. Ctrl/Cmd+K opens the integrated search dialog.
- Mood values, finance records, reminder lists, reminder associations, and reminder
  history remain owner-only. Instance and Space administrators gain no access to
  another person's records. Shared Memo content does not expose mood values.
- Comments follow upstream's independent lifecycle and default to PRIVATE when
  no visibility is supplied. SPACE visibility still requires active membership.
- Team reminders remain a future task in [TODO.md](TODO.md).

## Database and API compatibility

Existing fork migrations in 0.31–0.35 retain their names and sequence. Upstream
migrations run afterward in 0.36. The schema sequence is internal and independent
of the product release number: the resulting SQLite/MySQL version is 0.36.5,
and PostgreSQL is 0.36.6 (including its username collation migration).

The upgrade preserves original Memo identifiers, payload mood values, attachment
references, finance amounts/balances, reminders, links, and occurrence snapshots.
Full v0.33.6 schema fixtures for all three drivers are under
`store/test/testdata/fork-v0.33.6/`. The upgrade regression test compares every
legacy column in the relevant tables and repeats migration to model a restart.
It also checks that deleting a linked Memo detaches its reminder without deleting
completion history. This verifies representative fixtures, not the user's live
database, which was not used for development.

SHORTCUTS settings migrate to MEMO_VIEWS. Existing views are not overwritten if
both keys are present. Legacy Shortcut REST/Connect methods adapt to the same
Saved Views storage and enforce the same ownership checks; they do not maintain
a second copy. Legacy MCP shortcut listing remains available alongside view and
Space discovery.

The fork's `Memo.mood_level` keeps protobuf field 19; `Memo.space` uses field 20.
The generated Go, TypeScript, and OpenAPI outputs match these sources. JSON/REST
uses the official Space field name. Unmodified binary protobuf clients compiled
against upstream's conflicting field 19 need regeneration against this fork.

Instance URL and instance access mode are separate. When no explicit access
setting exists, initialization preserves the old effective behavior using the
stored/effective URL and the existing public-Memo switch. Editing a URL later
does not silently open anonymous access. Disabling public visibility keeps the
author's old public Memos readable to that author.

## Remaining product boundaries

Mood history is still stored in the Memo payload. Deleting the Memo removes that
mood from statistics; independent mood snapshots are a documented future task.
Finance transaction deletion retains the existing balance-adjustment semantics;
a separate immutable finance audit ledger is also deferred in TODO.md.

A production rollout should use a complete pre-upgrade database and attachment
backup. Test migration on a copy first. Reverting only the binary after applying
the new schema is not a supported rollback; restore the matching pre-upgrade
backup and binary together. Password protection is visual access control within
an authenticated app session, not encryption at rest. System biometrics and
WebAuthn/passkey registration are not included in v0.34.
